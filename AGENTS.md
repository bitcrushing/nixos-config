# AGENTS.md

Personal NixOS + home-manager flake for one machine (hostname `PC`, user `bitcrushing`). No test suite, no CI — building the system is the verification.

## Commands

- Verify changes: `nixos-rebuild build --flake ~/nixos#PC |& nom` (shell alias `nrb`)
- Apply: `sudo nixos-rebuild switch --flake ~/nixos#PC |& nom` (alias `nrs`); `test` instead of `switch` activates without touching the boot menu (`nrt`)
- Format: `nix fmt` (nixfmt via the flake formatter). Match existing nixfmt-rfc style.
- Update inputs: `nix flake update`

Aliases are defined in `home.nix`; changes to them only take effect after a rebuild. `nom` is nix-output-monitor — piping is optional but expected.

## Architecture

- `flake.nix` wires `home.nix` in via the home-manager NixOS module (`home-manager.users.bitcrushing`), with `useGlobalPkgs`/`useUserPackages` — home-manager packages come from the same nixpkgs as the system.
- **`theme.nix` and `niri.nix` are NixOS modules that also inject home-manager config** via `home-manager.users.bitcrushing` — their HM settings merge with `home.nix`, not conflict. When editing them, edit both layers in the same file.
- `theme.nix` defines `options.theme.palette` (a `mkOption`); `niri.nix` and others read colors via `config.theme.palette`. Reuse it rather than hardcoding hex.
- Custom packages in `pkgs/` (pipeasio, atkinson-nerdfont) are consumed with `callPackage` at the use site; there is no overlay.

## Constraints

- **Never edit `hardware-configuration.nix`** — generated by `nixos-generate-config`.
- **Never change `system.stateVersion` / `home.stateVersion`** (currently 26.05).
- Neovim plugins are NOT nix-managed: `home.nix` only contains lazy.nvim bootstrap Lua; plugins install to `~/.local/share/nvim` at runtime. Don't move plugin specs into nix.
- LSP servers are deliberately installed via `home.packages` with `mason = false` in the nvim config (mason can't work on NixOS without npm). Keep new servers on that path.
- Long comments above hacks (usbhid numpad quirk, nix-ld for Proton/opentrack, PipeASIO home activation, Discord portal routing) document real hardware/runtime traps — preserve the explanation when editing the code.
- The PipeASIO activation script in `home.nix` copies files into `~/.local/lib/wine` on every activation; `pkgs/pipeasio` changes only reach Wine/Proton after a `switch`.
